# Working principles

- The user is ahadik on Sleeper; league ID: 1400628784381612032.
- The user is new to football and wants to maximize their chance of winning this agent-managed league. Explain decisions plainly.
- Prefer deterministic code and scripts for data retrieval, validation, scoring, calculations, simulations with recorded seeds, optimization, and repeatable operations.
- Codex orchestrates a reusable system; it must not make direct external API calls. Write or extend saved scripts/commands that execute through the appropriate central API client/controller, then run those commands and analyze their outputs. This applies to diagnostics and credential checks as well as production collection. Do not use ad hoc curl, inline Python/JavaScript HTTP calls, browser fetch, or connector tools as substitutes for project API controllers.
- Minimize one-off code execution. Recurring retrieval, inspection, transformations, validation and reporting belong in reusable modules with documented command interfaces and structured outputs. When a needed operation has no command, implement the command first rather than recreating it in each conversation. Ordinary file reads, code edits and test-runner invocations remain appropriate development tools.
- FantasyPros access goes through `fantasypros.get_fantasypros`; Sleeper reads currently go through `draft.fetch` via saved commands such as `draft.py` and `controller.py`. New providers need a central client before use. Keep authentication, quotas, retries, caching and error handling in the provider layer, not scattered through callers. Do not imply the simpler Sleeper client already has all FantasyPros safeguards.
- The agent chooses strategy and invokes commands; scripts own data access, computation and durable state. Keep browser draft/queue actions within the separately authorized Computer Use workflow; browser control is not permission to call undocumented APIs. Future MCP tools should wrap the same application services, not duplicate provider access.
- Reserve inference for analysis, strategy, interpreting evidence, and actions that computation does not handle better. Strategic inference should consume computed analyses and consider expected opponent behavior.
- Keep source timestamps, assumptions, and calculation outputs separate from strategic judgments. Do not invent projections or substitute stale season data without explicit disclosure.
- For the initial draft, prioritize a minimal local tool with saved data and manual fallbacks over cloud infrastructure.
- Before operating any draft, and after resuming from conversation compaction or interruption, read `docs/DRAFT_RUNBOOK.md`. Its queue, turn-verification, timeout-recovery, and checkpoint procedures apply throughout the draft. Mock reports are evidence, not a target roster.
- Use `controller.py` and `docs/CONTROLLER.md` for draft supervision: start the read-only watcher, record real browser observations, run `prepare` before a selection, and reconcile pending picks. Never treat a recommended queue as applied, bypass a blocker to save time, or claim the controller itself executes browser actions. On resume re-run status; saved readiness expires.
- Sleeper's documented public API is read-only. Do not implement undocumented account writes or evasive automation.
- Before using FantasyPros data, read `docs/FANTASYPROS.md`. Follow its endpoint/scope, identity mapping, scoring-coverage, timestamp, quota and credential guidance. Keep provider facts separate from strategy; do not treat consensus rank spread as point variance or a suggested queue as applied. Never print `.env` or authentication headers.
- Route every FantasyPros read through `fantasypros.get_fantasypros` using the shared default cache directory. Do not bypass the persistent quota/cooldown or routinely force refresh. The client's basic response checks do not replace endpoint-specific validation or establish production entitlement.
- The future cloud backend must expose an authenticated MCP interface for ChatGPT access on the go. Keep computation independent of the MCP adapter, desktop session, and chat history. Follow docs/MCP_DESIGN.md. Native mobile compatibility must be verified on the user's account before claiming support.
